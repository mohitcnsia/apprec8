## 1. Summary of Changes

### Part 1: Channel Separation & Manifest Enforcement
- **Goal:** The real app (Play Store, `com.mohitchilkoti.apprec8`) must strictly receive updates published on the `production` channel. The test app (`com.mohitchilkoti.apprec8.test`, distributed via Firebase App Distribution to `mohitchilkoti@gmail.com`) must strictly receive updates on the `preview` channel.
- **`android/app/build.gradle`:**
  - In `flavorDimensions "appVariant"`, set `manifestPlaceholders = [expoUpdatesChannel: "production"]` for the `real` flavor.
  - Set `manifestPlaceholders = [expoUpdatesChannel: "preview"]` for the `preview` flavor.
- **`android/app/src/main/AndroidManifest.xml`:**
  - Added meta-data:
    ```xml
    <meta-data
        android:name="expo.modules.updates.UPDATES_CONFIGURATION_REQUEST_HEADERS_KEY"
        android:value="{&quot;expo-channel-name&quot;:&quot;${expoUpdatesChannel}&quot;}" />
    ```
  - This hard-codes the Expo update request header at native compile time, preventing any test build from listening to production or vice versa.
- **`app.config.js`:**
  - Configured `updates.channel: isTest ? "preview" : "production"` to ensure runtime configuration aligns with the flavor.
- **Publishing Rule on Board (`docs/agents/BOARD.md`):**
  - Added strict policy at the top of the board:
    ```markdown
    > ⚠️ **PUBLISHING CHANNEL RULE (G117):**
    > - Real app (Play Store / 20.0.30+): listens to EAS channel **production**. Only Claude runs `eas update --channel production`.
    > - Test app (App Distribution / 20.0.32): listens to EAS channel **preview**. Gemini publishes ONLY with `eas update --channel preview`.
    > - Gemini NEVER runs `--channel production`. Any test published to production risks real users.
    ```
