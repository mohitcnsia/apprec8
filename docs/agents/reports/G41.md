### Step 5: Read-Only Firestore Rules Audit
Audited `firestore.rules` under current live rules:
1. **Can demo teacher read members of demo classes?**
   - **YES.** Under `match /classes/{classId}/members/{kidUid}`, rule allows read if `teachesClass(classId)`. In Demo School, `demo_teacher` is listed in `classes/{classId}.teacherIds`, so `teachesClass` returns `true`.
2. **Can demo teacher read questProgress of kids in demo classes?**
   - **YES.** Under `match /users/{userId}/questProgress/{questId}`, rule allows read if `request.auth.uid in parentUids` OR `classIds.hasAny(teachesClassIds)`. Kids in Demo School have `classIds: ['demo_class_5a']` and `demo_teacher` has `teachesClassIds: ['demo_class_5a', 'demo_class_5b']`, which satisfies `hasAny`.
3. **Can demo_parent read users/demo_kid_login?**
   - **YES.** Under `match /users/{userId}`, rule allows read if `request.auth != null && request.auth.uid in resource.data.get('parentUids', [])`. In Demo School, `users/demo_kid_login` has `parentUids: ['demo_parent']`, matching `request.auth.uid`.
