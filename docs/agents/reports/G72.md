## 2. Root Cause Analysis

### Why the update rule denied Seema's first-run save:
In `firestore.rules` (lines 57–79):
```javascript
allow update: if request.auth != null && request.auth.uid == userId &&
  (
    (
      (resource.data.profileLastSavedAt == null || request.time - resource.data.profileLastSavedAt > duration.value(10, 'm')) &&
      'firstName' in request.resource.data &&
      ...
    )
    ...
  );
```
1. In Google Cloud Firestore Security Rules, accessing an undefined map key directly via `resource.data.property` throws an unhandled property error (`Property profileLastSavedAt is undefined on object`).
2. Unlike JavaScript, `resource.data.profileLastSavedAt` does not return `null` or `undefined` when the field is absent; it aborts rule evaluation, which immediately denies permission (`false`).
3. Because Seema's doc had no `profileLastSavedAt` field, `resource.data.profileLastSavedAt == null` crashed evaluation.
4. Furthermore, because `firstName` was missing from her document, `needsProfileSave` in `FirstRunScreen` saw `hasName === false`. It repeatedly attempted to execute the Firestore `.update()` rather than skipping the write for grown-ups.

## 6. Recommended Decision Record (DR) for Claude & Owner

To prevent any other user from hitting this failure when updating their profile:
In `firestore.rules`, change line 61 from:
```javascript
(resource.data.profileLastSavedAt == null || request.time - resource.data.profileLastSavedAt > duration.value(10, 'm'))
```
to use a safe presence check:
```javascript
(!('profileLastSavedAt' in resource.data) || resource.data.profileLastSavedAt == null || request.time - resource.data.profileLastSavedAt > duration.value(10, 'm'))
```
or `get()`:
```javascript
(resource.data.get('profileLastSavedAt', null) == null || request.time - resource.data.profileLastSavedAt > duration.value(10, 'm'))
```
