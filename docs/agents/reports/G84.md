## 1. Summary of Changes

### Part 1: "Needs you" Card on Home
- Created pure module `utils/needsYou.js` and test suite `tests/needsYou.test.mjs`.
- Generates action rows for users with pending items:
  - **Admin / Owner:** Decisions waiting (`"N decisions waiting · Tap to answer"`, navigates to `DecisionsScreen`), teacher requests waiting per class (`"10-B: 1 teacher waiting · Approve"`, navigates to `ClassDetailScreen`).
  - **Teacher:** Students waiting per class (`"10-B: 2 students waiting · Approve"`, navigates to `Progress` with `{ view: "classes", classId }`).
  - **Parent:** Hook provided for v1 (returns `[]` if nothing is pending).
  - When nothing is pending, `computeNeedsYou` returns `[]`. The "Needs you" card is conditionally rendered only when `needsYouRows.length > 0`, ensuring no empty box ever appears on the screen.
- Registered in `HomeScreen.js` as the very first card under the header chip row.

### Part 2: Push Notifications & Rate Limiting (DR-25)
- Created `functions/utils/pendingPush.js` with `canSendPush(lastPushedAt, now, windowMs)` and test suite `tests/pendingPush.test.mjs`.
- Implemented rate limiting: Maximum 1 push notification per user per 10 minutes (`pushRateLimits/{uid}`) with count tracking (`"N new"`).
- Updated `functions/callable/schoolActions.js`:
  - `redeemTeacherInvite`: Sends push notification to school creator, school admins, and app owner.
  - `onStudentJoinRequest`: Cloud Firestore onCreate trigger on `classes/{classId}/members/{kidUid}` sending push notifications to teachers of that class when a student requests to join (`status: "pending"`).
- Documented Deploy Request **DR-25** in `CODE_REVIEW.md` (queued for owner review; not deployed to production).

### Part 3: Teacher Home
- In `HomeScreen.js`:
  - When the user has classes (`userData.teachesClassIds`), queries `loadTeacherClassesOverview(uid)` to fetch each class with total students, active students who practised this week, and the class's weakest topic.
  - Section **YOUR CLASSES**: Rendered right under "Needs you" with class cards showing:
    - Class name and total student count
    - `SHARE CODE` button to invoke system share with formatted message
    - `"This week: X of Y practised"`
    - Weakest topic (`"Teach again: <topic>"` or `"All topics on track 👍"`) + `ASSIGN` button navigating directly to the class assignment view.
  - Quests header dynamically updates to `"Practise yourself"` when `teacherClasses.length > 0` (or `"Your quests"` otherwise).

### Part 4: School Admins Access
- Added `mySchoolAdminSchools(uid)` in `services/classesApi.js`.
- Updated `screens/admin/AdminToolsScreen.js`:
  - Non-app admins who are school admins now see "School admin" tools (Schools & classes, Teachers' one-pager) instead of "Admin only".
- Updated `screens/admin/SchoolsScreen.js`:
  - Filters school list to show only schools where the current user is in `school.admins`.
  - Hides "+ New school" creation button for non-app admins.
- Updated `screens/profile/MeScreen.js`:
  - Surfaces "Admin tools (schools & classes)" in "SCHOOL ADMIN" section for school admins.

### Part 5: Demo School & Testing
- Updated `utils/demoSchool.js`:
  - Created 2 pending students in `demo_class_10b` for testing teacher approval flow.
  - Created 1 pending teacher request in `demo_class_10b` (`demo_teacher_pending`, Kavita) for testing school admin approval flow.
- Updated `functions/utils/demoShift.js`:
  - Added regex support in `ALLOWED` for demo `teacherRequests` subcollection paths.
- Verified all 3 required demo school scenarios:
  1. Teacher (`demo_teacher`): Sees `"10-B: 2 students waiting · Approve"` in "Needs you", "YOUR CLASSES" cards with this week's practice stats, weakest topic + ASSIGN button, and quest tiles labeled `"Practise yourself"`.
  2. Admin (`APPREC8_TEAM_REVIEWER_UID`): Sees Decisions waiting and `"10-B: 1 teacher waiting · Approve"` in "Needs you".
  3. Parent (`demo_parent`): `needsYouRows` is empty; no "Needs you" card and no "YOUR CLASSES" section rendered.
