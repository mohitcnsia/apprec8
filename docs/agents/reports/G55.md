## 1. Problem Statement & Threat Model

### The Problem
Today, Apprec8 relies on an in-app 4-digit PIN stored as a salted scrypt hash in Firestore (`parentPins/{uid}`).
- When a child's play time expires (`TimeUpOverlay`), or when switching back from a child profile to the parent profile, the app asks for the 4-digit PIN.
- If wrong 5 times, it enforces a 15-minute lockout on the server (`switchToParent`).
- **Critical Gaps:**
  1. There is no "Forgot PIN?" recovery path. A parent who forgets their 4-digit PIN is blocked.
  2. If a naive "Forgot PIN" or "Sign in again" is added, a child holding their parent's phone can easily reset it (since Google Sign-In frequently signs in silently without prompting for credentials).
  3. A parent must **never be locked out of their phone** or left stranded without an escape hatch.

### Threat Vectors & Anti-Abuse Rules
1. **Child Guessing PIN:** Protected by server-side brute-force throttling (5 failed attempts → 15-minute cooldown).
2. **Child Abusing "Forgot PIN":**
   - The primary unlock & reset gate is the **phone's own screen lock** (biometric fingerprint / face ID or device PIN/pattern). A child cannot fake their parent's biometric or device lock.
   - For rare devices without any OS screen lock: requires explicit re-authentication **AND enforces a mandatory 1-hour security time delay** before the new PIN becomes active. A child cannot bypass it in a single sitting.
3. **Parent Notification:** Every PIN change or reset triggers an immediate push notification to parent devices and places an alert banner in the parent's Me tab: *"Your Apprec8 parent PIN was changed. Not you? Tap to reset."*
4. **Zero Parent Lockout Guarantee:**
   - Android Screen Pinning can always be exited by holding Back + Home / Overview, or by rebooting the device.
   - Uninstalling the app and reinstalling completely resets local lock state without losing children's stars or progress (all progress lives in the Firestore cloud).
   - Emergency admin reset via support email.

## 3. Implementation Details

### Step 1: Native Phone Lock (`services/localAuth.js`)
- Install `expo-local-authentication` (`npx expo install expo-local-authentication`).
- Wrap inside `services/localAuth.js` with runtime capability guards (so builds without the native module gracefully fall back to App PIN):
  ```js
  let LocalAuth = null;
  try {
    LocalAuth = require("expo-local-authentication");
  } catch (e) {
    // Fallback for environments where module is not linked
  }

  export async function isDeviceLockAvailable() {
    if (!LocalAuth) return false;
    const hasHardware = await LocalAuth.hasHardwareAsync().catch(() => false);
    const isEnrolled = await LocalAuth.isEnrolledAsync().catch(() => false);
    return hasHardware && isEnrolled;
  }

  export async function authenticateWithDeviceLock({ promptMessage }) {
    if (!LocalAuth) return { success: false, error: "not_available" };
    return await LocalAuth.authenticateAsync({
      promptMessage: promptMessage || "Unlock to switch to parent profile",
      cancelLabel: "Use App PIN",
      fallbackLabel: "Use App PIN",
      disableDeviceFallback: false,
    });
  }
  ```

### Step 2: Server-Side Functions (`functions/callable/familyActions.js` - DR Proposal)
1. **`switchToParentWithDeviceLock`:**
   - Callable by child session on phone where biometric verification succeeded.
   - Validates caller is child account linked to parent.
   - Issues custom auth token for `parentUid`.
2. **`resetParentPin`:**
   - Callable by parent account.
   - Accepts `{ newPin, authType: "deviceLock" | "delayed" }`.
   - If `authType === "deviceLock"`: updates `parentPins/{uid}` with new scrypt hash + salt immediately.
   - If `authType === "delayed"`: writes `pendingPin: { hash, salt, activeAt: Date.now() + 3600000 }` to enforce the 1-hour anti-abuse delay.
   - Triggers push notification to parent tokens via `sendPushToUser`.
3. **`adminResetParentPin`:**
   - Owner/admin only (`isAdmin(context.auth.uid)`).
   - Accepts `{ email }`.
   - Deletes `parentPins/{targetUid}`, sets `users/{targetUid}.hasParentPin = false`.
   - Records audit entry in `adminAuditLogs`.

### Step 3: Admin CLI Tool (`scripts/admin/resetPin.cjs`)
- Standalone CLI for owner/support operator:
  ```bash
  node scripts/admin/resetPin.cjs parent@example.com
  ```
- Validates parent email, verifies account is not a child profile, removes `parentPins/{uid}`, clears `hasParentPin` flag.
- Safe, audited, reproducible.

### Step 4: UI & Screen Experience

#### A. `ParentPinScreen.js`
- **Phone Lock First:** When opening in `"unlock"` mode, immediately launches device biometric / screen lock prompt if available.
- **Fallback to App PIN:** If cancelled or unavailable, shows 4-digit PIN pad.
- **"Forgot PIN?" Button:**
  - If phone lock available: prompts phone lock → on success, allows setting new 4-digit PIN twice.
  - If phone lock not available: initiates re-auth + displays 1-hour security cooldown timer.
- **"Locked out?" Sheet:**
  - Explains 3 clear recovery paths:
    1. *Use your phone's fingerprint, face ID, or phone PIN.*
    2. *Uninstall Apprec8 (Settings → Apps → Apprec8 → Uninstall) and reinstall: your child's stars, streak, and progress are safe in the cloud.*
    3. *Email support from your registered Google account for an instant reset.*

#### B. `TimeUpOverlay.js`
- Displays "Unlock with Phone Lock / Fingerprint" as primary action button.
- Secondary button: "Enter App PIN".
- Footer reminder: *"To exit app pinning at any time, press and hold Back and Home, or restart your phone."*

#### C. `MeScreen.js` / Admin Tools
- Under "Admin tools" (owner only): **Reset a parent's PIN**.
- Input parent's email → confirmation dialog → calls `adminResetParentPin`.
