# G65 Report: 🚩 Report a Mistake on Reading & Study Pages

**Date:** 2026-11-07  
**Branch:** `gemini/g65-report-reading`  
**Owner Problem Addressed:**
> "Pratha found a mistake, no way to report it."

---

## 1. Problem & Architecture

- **Previous State:** Quiz questions had a 🚩 button (`ReportQuestionButton.js`), but study pages (`Apprec8Reader.js`) only had a developer `FeedbackFAB` hidden behind an undocumented corner triple-tap gesture. The modern Learn cards (`components/learn/LearnCards.js`) had no report button at all.
- **Goal:** Provide a small, accessible 🚩 button in the top corner of both Learn cards and full study reading pages that writes directly to the existing `userFeedback` collection using the `entryPoint: "report_flag"` pattern, compatible with the existing `onQuestionReported` trigger.

---

## 2. Changes Made

### A. Pure Logic & Reason Mapping (`utils/studyReport.js`)
- **Child-Friendly Tap Reasons:**
  1. `"wrong_fact"`: Label `"Wrong fact"`, mapped to server category `"wrong_answer"`.
  2. `"confusing"`: Label `"Confusing"`, mapped to server category `"confusing"`.
  3. `"spelling"`: Label `"Spelling"`, mapped to server category `"spelling"`.
  4. `"picture_missing"`: Label `"Picture missing"`, mapped to server category `"media_broken"`.
- **Target ID Generator (`studyReportId`):**
  - Card-specific: `${contentId}#card-${cardIndex}` (e.g. `science-earth#card-2`).
  - Section-specific: `${contentId}#section-${section}`.
  - Page-level fallback: `${contentId}`.
- **Payload Builder (`buildStudyReportPayload`):**
  - Pure function creating the `userFeedback` payload with `entryPoint: "report_flag"`, `feedbackType: "issue_report"`, `contentContext` containing `type: "study_content"`, `parentId: contentId`, `cardIndex`, `section`, and `titlePreview`.
  - 300-character safety truncation for notes and previews.

### B. Service Extension (`services/reportApi.js`)
- Added `submitStudyReport(r)`:
  - Writes directly to `userFeedback` (offline-capable).
  - Deduplicates locally via `AsyncStorage.setItem("reported_" + targetId, "1")`.
  - Re-exports `STUDY_REPORT_REASONS` and `studyReportId`.

### C. UI Component (`components/quiz/ReportStudyButton.js`)
- Small top-corner button with `alert-circle-outline` icon and `"Something's wrong here"` accessibility label.
- Shows `"✓ Reported"` chip once reported on that device.
- Bottom sheet modal displaying:
  - Header: `"Something's wrong here"` and card/page title.
  - 4 tap-only chips for the child.
  - Safe free-text rule: Uses `useCanWriteFreeText()`. Children see `"Something else? Ask a grown-up to tell us."` with no text box; supervised/adult accounts get the optional note input.
  - `Cancel` and `Send` buttons.

### D. Screen Integrations
1. **Learn Cards (`components/learn/LearnCards.js`):**
   - Wired `ReportStudyButton` in `s.top` beside the card count.
   - Automatically passes active `cardIndex` (or `"summary"`), card title, and text preview.
   - Forwards `questContext` to ensure `questId` and `nodeId` are attached to reports.
2. **Old Reader (`components/common/reader/Apprec8Reader.js`):**
   - Placed `ReportStudyButton` at the top right of the reader view.
   - Passed `questContext` to `LearnCards`.

### E. Unit Tests (`tests/studyReport.test.mjs`)
- Tested target id formatting, reason definitions, server category compatibility against `functions/utils/reportRules.js` `R.REASONS`, payload structure, and character truncation.
- Added to `npm test` script in `package.json`. All 49 test suites pass.
