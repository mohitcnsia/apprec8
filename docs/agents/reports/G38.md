## Key Review Findings Summary

1. **Global Leaderboard & Rank:**
   - `getLeaderboard` (`functions/callable/userActions.js`): Currently orders by `stats.totalStars desc` with no `isDemo` check. In-memory buffer filtering fails if 44 demo kids take up top slots.
   - **Critical finding omitted in spec:** `getCurrentUserRank` uses server-side `.count().get()` on `where("stats.totalStars", ">", score)`. Firestore `.count()` cannot be filtered in memory and will degrade real kids' ranks.
   - **Recommendation:** Do NOT set `stats.totalStars` on demo user documents. Omission of the field automatically excludes demo accounts from both `getLeaderboard` and `getCurrentUserRank` queries natively with zero code changes and zero extra reads.

2. **Admin Dashboard Progress:**
   - `listKidProgress` (`services/adminApi.js`) uses collection group `questProgress` without reading parent `users/{uid}`.
   - **Requirement:** `isDemo: true` must be stored directly on each `users/{uid}/questProgress/{questId}` document at seed time.
   - `AdminDashboardScreen.js` needs a toggle to hide demo kids by default.

3. **Class Joins & Visibility:**
   - `joinClass` and `findClassByCode` (`services/classesApi.js`) and `approveMember` (`functions/callable/schoolActions.js`) currently have no `isDemo` checks. Real kids entering demo codes could join demo classes, and demo accounts could request to join real classes.
   - `listSchools()` reads all schools and would expose "Demo School (not real)" to all users in school lists.
   - **Recommendation:** Do not register public class codes in `classCodes` for demo classes; add matching `caller.isDemo === class.isDemo` validation in `joinClass` and `approveMember`; update Firestore rules; filter `listSchools()`.

4. **🚩 Tallies & Reports Auto-Hide:**
   - `onQuestionReported` triggers on all `userFeedback` (`entryPoint == "report_flag"`).
   - If demo users flag questions, it tallies distinct kids and can **automatically hide questions from real kids across the app** if `hideAt` (3) is reached.
   - **Requirement:** Add an early exit in `onQuestionReported` for `isDemo: true` or demo UIDs. Never write mock reports to `userFeedback`.

5. **`seedDemoSchool` Cost & Security:**
   - Must check `isAppAdmin(context.auth.uid)` and set `maxInstances: 1`.
   - **Cascade Deletes:** Firestore does NOT delete subcollections on document deletion. Reset routine MUST use `admin.firestore().recursiveDelete()` on all demo user docs (to delete `questProgress` subcollections) and demo class docs (to delete `members`, `cache`, etc.). Otherwise, orphaned `questProgress` docs will permanently pollute `collectionGroup` queries.
   - Auth idempotency: Must check `getUserByEmail` before creating Auth users to avoid `auth/email-already-exists` crashes on re-seed.
   - Operations: ~600 writes to seed, ~600 reads/deletes to reset, well within Firebase free tier limits.
