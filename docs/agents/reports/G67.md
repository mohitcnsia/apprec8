## Executive Summary

The Progress tab currently serves four distinct audiences through a single screen container with role-dependent tab segments:
1. **Child ("Me"):** Streak calendar, stars, weekly question count, accuracy percentage, quest progress bars, "Work on these" (weak topics), "Great at" (strong topics), and leaderboard button.
2. **Parent ("My children"):** 7-day practice calendar, minutes practised, week-over-week trend, subject cards (done/total topics, strong topics, practice recommendations), "One thing to do at home", and missed questions.
3. **Teacher ("My classes"):** Class selector, weekly overview (participation count, "Reteach one thing", "Who needs you"), full topic assignment creator, and individual student progress table.
4. **Owner / Admin ("Kids · Reported"):** Embedded admin dashboard with 4 quest filters, time range filters (Today, This week, All), kids list, and reported question issues.

This investigation resolves the mystery of **why Pratha's weekly summary appeared blank** even after playing, captures emulator screenshots of every view across all four roles, and provides an objective audit of what each view shows today, where it clutters or breaks, and actionable discussion points for the upcoming four-dashboards redesign.

## 1. Why the Weekly Summary is Blank (Root Cause Analysis)

### The Problem
Owner note (2026-11-07): *"Pratha played but the weekly summary is blank..."*

In testing on device and emulator, when viewing Pratha's card under **Progress → My children**, the screen displayed:
> **THIS WEEK**  
> Practised 0 of 7 days · 0 min  
> `[S] [M] [T] [W] [T] [F] [S]` (all dots grey)  
> *Pratha didn't practise this week. A short, friendly reminder helps more than a long talk.*

Even though Pratha had engaged with the app, the summary registered zero activity.

### Tracing the Data Flow
The parent week summary is computed by [`parentWeek()`](file:///Users/mohitchilkoti/Documents/projects/apprec8-gemini/utils/parentWeek.js#L100-L147) in `utils/parentWeek.js`, rendered by [`ParentWeekCard`](file:///Users/mohitchilkoti/Documents/projects/apprec8-gemini/components/parent/ParentWeekCard.js#L30-L90):

1. **What `ParentWeekCard` reads:**
   - It iterates over bundled quests: `QUESTS.filter((m) => !m.quest?.draft && nodesForGrade(m.nodes, child.grade).some((n) => n.kind === "main"))`.
   - For each quest (`english-quest`, `science-quest`, `word-bank`, `word-power`), it executes a one-time read of:
     `users/{childUid}/questProgress/{questId}`
   - Specifically, it extracts `snap.data()?.stats`.

2. **How `parentWeek` computes active days:**
   ```javascript
   // utils/parentWeek.js lines 70-81
   function weekDays(statsList, now, words) {
     const out = [];
     for (let i = 6; i >= 0; i--) {
       const ms = now - i * DAY;
       const key = dayKey(ms); // "YYYY-MM-DD"
       const on = statsList.some((s) => (s?.daily?.[key]?.answered || 0) > 0);
       out.push({ key, label: words.days[dow], on });
     }
     return out;
   }
   ```
   A day is marked active (`on: true`) **only if** `questProgress.stats.daily[dayKey].answered > 0`.

3. **How `parentWeek` computes time:**
   ```javascript
   // utils/parentWeek.js line 105
   const timeMs = statsList.reduce((s, st) => s + summarize(st, "week", now).timeMs, 0);
   ```
   `summarize()` sums `st.daily[dayKey].timeMs` for the past 7 days. If `stats.daily` has no entry in the last 7 days, `timeMs = 0`.

4. **The Critical Blanking Gate:**
   ```javascript
   // utils/parentWeek.js line 144
   nothingText: daysOn === 0 ? w.nothing(name) : null,
   ```
   In `ParentWeekCard.js` (lines 78-90), if `w.nothingText` is truthy, the entire subject breakdown (strong topics, practice recommendations, progress ratios) is **completely hidden and replaced by `nothingText`**!

### The 5 Root Causes

| # | Root Cause | Exact File & Mechanism | Impact on Pratha |
|---|------------|------------------------|------------------|
| **1** | **Practice Papers do not write `stats.daily`** | In `services/paperApi.js` (`savePaperResult`, lines 59–100), completing a 50-question Practice Paper records a document in `questAttempts` (`questId: "practice-papers"`), writes to `paperHistory` in `AsyncStorage`, and updates mistakes via `addPaperMistakes`. **It never calls `saveStats()` or `updateStats()`**. Furthermore, `ParentWeekCard` only scans `QUESTS`, ignoring `questAttempts` and `practice-papers` entirely. | A child can complete a full 50-question mock exam over 40 minutes, and the parent card shows **0 minutes and 0 days practised**. |
| **2** | **Learn Cards / Study Pages do not log activity** | In `services/englishQuestApi.js` (`markStudyNodeCompleted`, lines 128–130) and `updateNodeProgress` (lines 100–125), reading study pages or flipping through Learn Cards only updates `nodes.{nodeId}.status = "completed"`. **It never writes to `stats.daily` or `stats.timeMs`**. | 20 minutes spent reading concepts registers as 0 minutes of practice. |
| **3** | **Legacy Space Olympiad Quizzes write to legacy paths** | The Space Olympiad quest writes stars to `users/{uid}/stats.totalStars` and progress to `quest_nodes`. It does not write to `users/{uid}/questProgress/{questId}`. | Any practice on the legacy Space map is completely invisible to the Progress tab. |
| **4** | **Abandoned / Mid-Quiz Exits are discarded** | In `QuizScreenV2.js` (line 489), `saveQuestAttempt()` is invoked only when the quiz finishes or hearts run out. If a child answers 4 questions and taps the back button or closes the app, nothing is committed to `stats.daily`. | Partial effort is lost from weekly statistics. |
| **5** | **Zero-Activity All-or-Nothing UI Blanking** | When `daysOn === 0`, `ParentWeekCard.js` completely replaces the subject cards with the discouraging message: *"Pratha didn't practise this week."* | Even if a child had completed 20 topics earlier, the parent sees no topics, no strengths, and no next steps. |

## 4. Key Takeaways for the Redesign Discussion

Connecting these factual findings to the design brief in `docs/product/PROGRESS_REVIEW_TODO.md` and the concept mockup `docs/product/progress-concept-chatgpt.png`:

1. **Unify Activity Logging Across All Features (Technical Fix):**
   - Practice Papers, Learn Cards, Endless Practice, and Quests must all write to a unified daily activity record (`stats.daily`).
   - A single helper function (e.g. `recordDailyActivity({ questId, timeMs, answered, correct })`) should be called by `savePaperResult()`, `saveQuestAttempt()`, and `markStudyNodeCompleted()`.

2. **Abolish All-or-Nothing Zero-Activity Blanking:**
   - A parent should **always** see where their child is, what they are strong at, and what they need help with, even if the child was inactive this week.
   - The banner should simply say *"No practice this week"*, while keeping the subject roadmap and conversation starters fully visible.

3. **Transition from Activity Counts to Mastery Levels:**
   - Today's dashboards show raw question counts (`183 Qs`) and aggregate percentages (`85%`).
   - As proposed in ChatGPT's brief and Claude's notes: measure actual mastery (e.g. *New → Practising → Mastered → Retained*). Mastery should only advance on fresh questions, varied difficulty, and retention checks after multiple days.

4. **De-clutter the Multi-Tier Tab Navigation:**
   - Replace the 4 stacked tiers of horizontal pills in the Admin view with a clean drawer or dropdown filter.
   - Separate Admin monitoring tools (Kids and Reported Issues) from personal learning progress.
