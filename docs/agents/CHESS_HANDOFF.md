## How to drive the owner's phone (OnePlus 9 Pro, 1080×2412) — Opus does the walks

- `adb` only works OUTSIDE the sandbox; macOS has no `timeout` (use `perl -e 'sleep N'`).
- Dev build: `adb install -r android/app/build/outputs/apk/real/debug/app-real-debug.apk`,
  start Metro (`npx expo start`, background, DON'T pipe through `head` — SIGPIPE kills it),
  `adb reverse tcp:8081 tcp:8081`, launch
  `adb shell am start -a android.intent.action.VIEW -d "apprec8://expo-development-client/?url=http%3A%2F%2Flocalhost%3A8081"`.
- Walk by `adb exec-out screencap -p > file.png`, read the PNG, `adb shell input tap X Y`.
  **Screenshot first, tap second — never tap from a remembered layout** (a blind tap once
  landed on Delete-account; phrase-gate saved it). Full JS reload: `adb shell input keyevent 82`
  → Reload (fast refresh doesn't remount native inputs).
- Sign-in: Continue with Google → mohitchilkoti@gmail.com. Owner extras: Me → More fold →
  Owner extras. Evidence screenshots → `docs/release/screenshots/`; afterwards scan
  `adb logcat -d | grep -E "SoftException|FATAL|Invalid"` (must be empty) and leave Owner
  extras ON. The phone keyboard force-capitalises after "1." — that's why the parser forgives it.
